## 事前作業：APIドキュメントをAIに読み込ませる

OrdinalX APIについてAIに質問するときは、まずCodexにAPIドキュメントを確認させます。

### AIへのプロンプト

```text
以下の資料を順番に確認してください。

1. docs/api/openapi.json

 全エンドポイントの定義と実例を確認してください。

2. 稼働サーバー

https://bsvapi01.cds.tohoku.ac.jp/swagger/

以降の質問には、これらの資料を根拠として回答してください。

ドキュメントに書かれていない内容については推測せず、
確認できない場合は、その旨を明記してください。
```

## ワーク1：OrdinalXでできることをAIに説明させよう

ここからは、CodexにOrdinalXのAPIドキュメントを読ませながら、OrdinalXで何ができるのかを調べます。

### STEP 1：OrdinalXでできることを調べる

資料の読み込みが終わったら、続けて次のように質問します。

#### プロンプト

```text
今読んだドキュメントの内容をもとに、
OrdinalXを使って何ができるのか説明してください。

特に、以下について整理してください。

- BSVに関する機能
- NFT (Non Fungible Token)に関する機能
- FT（Fungible Token）に関する機能
- その他の主な機能

それぞれについて、
「何ができるのか」を初心者にもわかる言葉で説明してください。

ドキュメントに書かれていない内容は推測しないでください。
```

### STEP 2：根拠となるAPIを確認する

AIの説明だけをそのまま信用するのではなく、実際にどのAPIを根拠に説明しているのか確認してみましょう。

#### プロンプト

```text
今説明した各機能について、
その機能を実現するために使用するAPIのエンドポイントを示してください。

以下の形式で整理してください。

- 機能名
- できること
- 使用するAPI
- HTTPメソッド
- 主なパラメータ

ドキュメントに書かれていない内容は推測せず、
わからない場合は
「ドキュメントから確認できない」
と答えてください。
```

### STEP 3：表に整理する

最後に、OrdinalXでできることを一覧表に整理してみましょう。

#### プロンプト

```text
ここまで調べた内容をもとに、
OrdinalXでできることを表にまとめてください。

列は次の4つにしてください。

機能分類 ／ できること ／ 関連API ／ 具体的な利用例

専門用語を使いすぎず、
これからブロックチェーンアプリを作る初心者向けに説明してください。
```

## ワーク2：AIと一緒にアプリを設計・開発しよう

OrdinalXで何ができるのかを確認したら、次は実際に自分で作りたいアプリを考えます。

AIにいきなりコードを書かせるのではなく、**アイデア → 仕様 → 実装 → テスト → 修正**という順番で開発を進めます。

### AI駆動開発の基本サイクル

1. 作りたいアプリをAIに伝える
2. AIに仕様書を作らせる
3. 人間が仕様書を確認・修正する
4. AIにコードを書かせる
5. 実際に動かしてテストする
6. おかしいところをAIと一緒に直す
7. もう一度テストする

**うまく動くまで、テストと修正を繰り返します。**

![AI駆動開発の流れ](1.png)

### STEP 1：作りたいアプリをAIに伝える

まずは、「どんなアプリを作りたいのか」をAIに伝えます。

この段階では、細かい技術仕様まで考える必要はありません。「こんなものを作りたい」というアイデアを、自分の言葉でAIに説明してみましょう。

#### プロンプト例

```text
BSVを送金できるシンプルなWebウォレットを作りたいです。

送金先のアドレスと送金額を入力して、
ボタンを押すとBSVを送金できるようにしたいです。

残高や送金結果も画面上で確認できるようにしたいです。

このアイデアについて、
これまで読み込んだOrdinalXのAPIドキュメントをもとに、
実現可能かどうか確認してください。

実現できる場合は、
どのような機能が必要になるか整理してください。

OrdinalXのドキュメントに書かれていない内容については、
推測せず、その旨を明記してください。
```

### STEP 2：AIに仕様書を作らせる

作りたいアプリのイメージが整理できたら、次にAIに仕様書を作ってもらいます。

文章だけではなく、画面構成や処理の流れもできるだけ視覚的に説明させてみましょう。

#### プロンプト例

```text
先ほど整理したアプリについて、
実装するための仕様書を作ってください。

これまで読み込んだOrdinalXのAPIドキュメントをもとに、
実際に実現可能な仕様にしてください。

仕様書には、少なくとも以下を含めてください。

- アプリの目的
- ユーザーができること
- 必要な画面
- 各画面に配置するボタンや入力欄
- ユーザーが操作したときの処理
- 使用するOrdinalXのAPI
- APIを呼び出す処理の流れ
- 必要になるデータ
- エラーが起きた場合の動作

また、文章だけではなく、
アプリ全体のイメージが視覚的にわかるようにしてください。

たとえば、

- 簡単な画面イメージ
- 画面遷移図
- ユーザーからOrdinalX APIまでの処理の流れ

などを使って説明してください。

専門知識がない人が見ても、
「どんなアプリを作るのか」
がイメージできる仕様書にしてください。

OrdinalXのAPIドキュメントに存在しない機能を、
勝手に仕様へ追加しないでください。
```

### STEP 3：仕様書を人間が確認・修正する

AIが作った仕様書が、そのまま正しいとは限りません。仕様書を見ながら、自分が本当に作りたいアプリになっているか確認します。

特に、以下の点をチェックしてください。

- 本当に作りたいものになっているか
- 不要な機能が入っていないか
- 必要な機能が抜けていないか
- 画面構成はわかりやすいか
- 操作方法はわかりやすいか
- OrdinalXで本当に実現できる内容か
- 使用するAPIは正しいか
- 処理の流れに不自然なところがないか

おかしいところや、変更したいところがあれば、AIに修正を依頼します。

#### プロンプト例

```text
この仕様書をブラッシュアップしてください。

以下の点を修正したいです。

- 不要な機能を削除してください
- 画面をもっとシンプルにしてください
- 操作の流れをもっとわかりやすくしてください
- OrdinalXのAPIの使い方に誤りがないか再確認してください

修正後の仕様書を、
全体がわかる形でもう一度提示してください。
```

#### 仕様書は何度直してもよい

仕様書は、一度で完成させる必要はありません。

**仕様書を読む → 気になるところを見つける → AIに直させる**

という作業を繰り返してください。実装を始める前に、「これなら作りたいアプリになりそうだ」と思える状態まで仕様を整理しましょう。

### STEP 4：仕様書をもとにAIにコードを書かせる

仕様が固まったら、いよいよ実装です。作成した仕様書をもとに、AIにアプリのコードを書いてもらいます。

#### プロンプト例

```text
この仕様書をもとに、
実際にアプリを実装してください。

OrdinalXを利用する部分については、
これまで読み込んだAPIドキュメントの仕様に従ってください。

まずは、
最小限の機能が動作するところまで実装してください。

必要なファイルは作成してください。

また、

- 作成したファイル
- 変更したファイル
- 各ファイルの役割
- アプリの起動方法

も説明してください。

OrdinalXに関係する処理については、
使用しているAPIエンドポイントも示してください。
```

### STEP 5：実際に動かしてテストする

コードが完成したら、実際にアプリを動かしてみます。AIが「完成しました」と言っても、本当に動くとは限りません。必ず自分で動作を確認してください。

たとえば、以下を確認します。

- アプリが正常に起動するか
- 画面が正しく表示されるか
- ボタンを押したときに正しく動くか
- 入力欄に入力した内容が正しく処理されるか
- OrdinalXのAPIを正しく呼び出せているか
- APIから正しいレスポンスが返っているか
- エラーが発生しないか
- 仕様書どおりの動作になっているか

### STEP 6：おかしいところをAIと一緒に直す

アプリを動かしていると、エラーが出たり、想定と違う動きをしたりすることがあります。その場合は、実際に起きた現象をAIに伝えて修正させます。

#### プロンプト例

```text
実際にアプリを動かしてみたところ、
問題が発生しました。

以下が現在の症状です。

【起きている問題】

ここに、
実際に起きた現象を書いてください。

【エラーメッセージ】

エラーメッセージが表示されている場合は、
ここにその内容を貼り付けてください。

原因を調べて修正してください。

ただし、
推測だけで修正するのではなく、
OrdinalXに関係する部分については
APIドキュメントをもう一度確認してから修正してください。

修正した箇所と、
なぜその修正が必要だったのかも説明してください。
```

### STEP 7：もう一度テストする

修正したら、もう一度アプリを動かして確認します。

**実装 → テスト → 修正 → テスト**

このサイクルを、うまく動作するまで繰り返します。

## AI駆動開発で大切なこと

AIを使った開発では、最初から完璧な答えやコードを出してもらう必要はありません。

**作ってみる → 動かしてみる → 問題を見つける → 直す**

という作業を繰り返しながら、少しずつ完成度を高めていきます。

### ポイント

- AIの回答をそのまま信用しない
- APIについては必ず公式の仕様を確認する
- 作りたいものを人間が決める
- AIが作った仕様を人間が確認する
- AIが書いたコードを実際に動かして確認する
- エラーが出たら、エラーの内容をAIに伝える
- 一度で完成させようとしない

**AIにすべてを任せるのではなく、人間が考え、確認し、AIと一緒に開発を進めることが重要です。**

## ワーク3：NFTの機能を追加する

作成したBSV送金アプリに、次は**NFTの機能**を追加します。

OrdinalXのAPIドキュメントを確認しながら、NFTの作成や送受信など、どのような機能を追加できるかAIと一緒に考えてみましょう。

開発の進め方は、ワーク2と同じです。

**仕様を考える → 仕様書を修正する → 実装する → テストする → 修正する**

ワーク2で作ったアプリを壊さず、NFT機能を追加していくことがポイントです。

## ワーク4：FTの機能を追加する

最後に、現在のアプリへ**FT（Fungible Token）の機能**を追加します。

OrdinalXのAPIドキュメントを確認しながら、FTの発行や送受信など、実装できる機能をAIと一緒に整理してください。

**仕様を考える → 仕様書を修正する → 実装する → テストする → 修正する**

これまで作った機能を残したまま、さらにFT機能を追加していきます。

## 完成イメージ

**BSV送金 → BSV送金 ＋ NFT → BSV送金 ＋ NFT ＋ FT**

一度にすべてを作るのではなく、小さく作って動作確認しながら、少しずつ機能を追加していきます。

## 終わったら：自由制作

FT機能まで実装が終わったら、自由に機能を追加したり、改良をしてみたり、好きな機能をもつ成果物を作ってみましょう。
